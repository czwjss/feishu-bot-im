# 飞书分身：使用与排障

飞书分身可以在普通 DSH 会话中主动以本人身份读写飞书，也可以监听私聊和指定群聊，并把新消息交给 Worker 自动处理。两种用法共用同一份用户授权和六个全局工具。

## 连接本人账号

1. 在 DSH 启用 `feishu-bot-im`，先配置一个飞书机器人应用及 App Secret。
2. 在飞书开发者后台开通[权限清单](feishu-scopes.md)中的用户权限，并发布应用版本。
3. 打开侧栏「飞书机器人IM」，选择对应机器人，在「状态」页的「分身状态」中点击「连接分身」，发起连接并扫码确认。
4. 授权完成后，状态页显示姓名、连接状态和凭证到期时间；进入「分身」页管理监听和 Worker。

连接使用 Device Flow，不需要重定向 URL 或本机回调端口。App ID / Secret 复用所选机器人的配置。

当前每个插件数据目录只保存一份用户授权和一份监听配置。授权与监听在实际关联的机器人下展示。切换应用或用户会替换这份授权，手动群聊沿用既有配置。私聊开关绑定开启时的授权账号，换账号后需要重新开启。取消授权请求后，旧请求不会重新开启等待状态或在后续用户信息查询完成时落库。

## 主动读写飞书

Host 默认注册以下工具，普通会话与 Worker 均可使用，无需安装专用预设。

| 工具 | 输入与用途 |
|---|---|
| `feishu_avatar_me` | 查询当前授权用户的姓名、open_id 等信息 |
| `feishu_avatar_chats` | 按群名或关键词查找本人已加入的群，返回候选群和 `chatId` |
| `feishu_avatar_messages` | 用 `chatId` 读取私聊 / 群聊历史；支持时间范围、分页和本次结果内的关键词筛选 |
| `feishu_avatar_send` | 用 `chatId`、`openId`、`email` 之一指定收件人；用 `text` 或 `path` 发送卡片、图片或文件 |
| `feishu_avatar_cloud` | 统一搜索云文档和知识库页面，读写云文档，管理云空间目录并上传、下载或覆盖普通文件 |
| `feishu_avatar_wiki` | 浏览知识空间、查看节点详情、读写正文、新建和移动页面、管理附件 |

文本卡片支持 Markdown、可选标题和标题颜色；传 `replyToMessageId` 可引用消息，需要同时提供原消息所属的 `chatId`，且仅支持文本卡片。发送前会核对原消息的会话，目标矛盾时不发送。
发送参数的当前校验上限为：正文 8,000 字符、标题 100 字符、图片 10 MiB、其他文件 30 MiB。相对文件路径以当前会话工作区为基准。

这些工具使用本人身份，`feishu_bot_*` 使用机器人身份。工具始终接受显式收件人参数，自动任务的目标会话由提示词约束。

知道群名时，先用 `feishu_avatar_chats` 搜索。出现同名或模糊结果时确认目标，再用返回的 `chatId` 读写会话。机器人未加入的群也可以查找，前提是授权用户已加入。见[群搜索参数](tools.md#分身按群名查找)。

历史查询使用 `limit`、`order`、`query`，不接受旧参数别名。关键词只在本页拉取结果内筛选，空结果也可能有下一页；根据返回的 `hasMore` 和 `pageToken` 继续读取。结果保留完整消息文本、ID 和带时区时间。

可以让分身「搜索飞书里的本周周报」或「列出我能访问的知识库」。用 `feishu_avatar_cloud.search` 搜到 Wiki 页面后，把结果里的 `target` 交给 `feishu_avatar_wiki`，也可以直接提供页面链接。分身可以查看标题、资源类型和父节点，创建 Docx 页面，或将已有页面连同子页面移到指定父页面或知识空间顶层。删除时默认把直属子页面移到上一级，明确要求时可连同子页面一起删除。

可以下载 Wiki 附件原文件、上传本地文件到指定页面，或覆盖原始文件节点的内容并保留文件 ID 和原名。下载保存到会话工作区内尚未使用的文件路径，上传和覆盖上限均为 20 MiB。操作受本人对目标资源的访问权限限制。参数见[云空间工具](tools.md#云空间与云文档)和[知识库工具](tools.md#知识库)。

云空间和知识库权限随「连接分身」一起申请。已有分身缺少权限时，例如移动页面所需的 `wiki:node:move`，在应用后台开通相应权限并发布版本，再从「状态 → 飞书分身」点击「重新授权」扫码。权限明细见[权限清单](feishu-scopes.md#更新已有授权)。

## 开启自动处理

打开侧栏「飞书机器人IM」→ 选择机器人，在「状态」配置自动回复，在「分身」管理监听会话：

- 授权用户与授权到期时间集中在「状态」页展示（`refresh_token` 当前有效期，随刷新更新）。该页直接展示授权详情，「重新授权」「刷新凭证」位于右侧；「…」中的「断开授权」需二次确认。
- **消息监听**：点击「开始监听」启用调度。群聊通过「添加群聊」逐个指定，可分别设置触发规则与回复对象。私聊通过「监听所有私聊」一键启用，默认关闭，开启后自动发现飞书目录返回的私聊。两类会话均可查看消息、待处理数量和关联 Worker。
- **自动回复设置**：直接位于状态页的分身信息下方，管理转人工关键词、Worker 分组与预设、分身回复规则。授权失效或缺少消息功能所需权限时隐藏，仅缺少新增云空间权限时仍可使用。

点击「查看消息」读取本地消息快照，按待处理、上下文消息和已排除分类。消息 ID 默认折叠；历史 Worker 也可以从这里内嵌打开。读取状态和查看消息不会触发派发。上下文消息是当前保留的背景，不是完整的历史批次输入或回复凭据。

分身页左侧显示监听会话，右侧直接展示选中会话的 DSH 原生 Worker，复用记录、输入和待处理交互。默认选中第一个会话，没有 Worker 时等待首次派发，不会因查看而创建。监听设置和消息详情在抽屉中打开，不中断 Worker 输入；授权详情、扫码流程和自动回复设置直接在状态页展示。窄屏点击会话进入对话，点击「会话列表」返回；「独立打开」才跳转到 DSH 主会话。查看历史 Worker 使用历史 Session ID，可「返回当前 Worker」。切换视图不停止 Worker，工作区中的原会话仍然可见。

卡片折叠和主面板内切换页签会保留编辑内容，已打开的内嵌会话在页签切换时保留引用。进入内嵌 Worker 前先提交分身编辑；切换机器人或独立打开前提交全部待保存配置，失败则停留并提供重试。扫码在状态页内进行，使用「取消扫码」结束当前请求；切换页签或机器人不自动取消。

| 设置 | 行为 |
|---|---|
| 全部消息 | 处理该会话中符合发送者规则的新消息。自动发现的私聊使用此模式，仅处理对方真人消息 |
| @我 / 回复我 | 群聊默认使用 |
| 关键词 | 关键词、@我、回复我满足任一条件即可 |
| 仅真人 / 包含机器人 | 群聊可选。开启包含机器人时，机器人与真人同等合批处理 |
| 转人工 | 命中后跳过当前待处理批次；后续消息继续正常处理。清空关键词可关闭 |
| Worker 工作区 / 预设 | 修改后，下次派发创建新 Worker；未指定时使用 DSH 默认工作区和 `standard` 预设 |
| 分身回复规则 | 所有自动 Worker 共用，编辑后自动保存，也可恢复默认模板 |

设置修改后自动保存。下拉框和开关即时提交；回复规则、转人工关键词和会话匹配关键词停止输入 600 毫秒后提交，离开输入框时立即提交，中文输入法组词期间暂停文本保存。「恢复默认模板」立即保存默认规则；空白内容保存为默认模板。保存状态与失败重试会直接显示在主面板。规则保存后从下一次模型请求生效，无需重建 Worker。

默认每 30 秒检查消息，再合批等待 30 秒；持续有新消息时最长等待 3 分钟，满 10 条立即派发。详细参数和边界以[监听与派发规则](user-message-monitor-design.md)为准。

「立即检查」拉取消息；「重试派发」尝试派发全部积压；单个会话的「派发本批」只处理该会话的待派发消息。新增群聊或开启私聊监听都从当时起处理新消息。停止全部监听会暂停未派发任务。关闭私聊开关会取消私聊的待派发批次，保留历史 Worker；再次开启后从新的起点处理。已被 Host 接收的任务继续执行。旧版手动添加的私聊不会自动打开私聊开关。

## 授权维护

- 「重新授权」通过扫码申请完整权限。「刷新凭证」续期当前授权。
- 「断开授权」取消设备授权请求并清除本地用户 token；它不是清空监听配置或撤销已接收任务的按钮。
- DSH 运行期间后台检查凭证；有效期取飞书实际返回值。过期且无法刷新时需重新连接。
- 状态页会提示缺少的 scope；调整期望权限不会给已有 token 自动增加权限，需要重新授权。

## 排障

| 现象 | 检查与处理 |
|---|---|
| App Secret 缺失、应用不可用 | 在对应机器人的设置里补齐凭证 |
| 授权报 `20027`，或接口报 `99991679` | 检查应用用户权限、发布版本，并重新授权 |
| 刷新报 `20037` / `20073` | 当前 refresh_token 已失效，重新连接 |
| 工具不存在 | 确认 Host 插件启用，重新加载插件；无需修改预设 |
| 添加后没有旧消息 | 新监听不回补历史；按需用历史查询工具读取 |
| 私聊未出现在监听列表 | 检查「开始监听」和「监听所有私聊」，再点「立即检查」。如有发现错误，私聊分区会提示。私聊范围由授权账号的飞书会话目录决定 |
| 新消息未入待处理批次 | 检查监听开关、触发模式、机器人开关及卡片是否仍在流式输出；本人消息只作为背景 |
| 有待处理消息但尚未派发 | 查看会话错误；检查 Worker 工作区 / 预设；可点击「处理待办」重试 |
| 待处理数归零但没有回复 | Host 接收任务即清队；查看对应 Worker，它可能尚未执行、决定不回复或执行失败 |
| 修改代码后行为未变化 | 重载 DSH 插件；源码更新不会自动替换已加载的模块 |

本地文件的位置、内容和保护方式见[开发架构](user-identity-architecture.md#持久化与并发)。
