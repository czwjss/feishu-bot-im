# 飞书分身：使用与排障

飞书分身提供两种能力：在普通 DSH 会话中主动以本人身份读写飞书，以及监听指定会话、把新消息交给 Worker 自动处理。两者共用同一份用户授权和三个全局工具。

## 连接本人账号

1. 在 DSH 启用 `feishu-bot-im`，先配置一个飞书机器人应用及 App Secret。
2. 在飞书开发者后台开通[权限清单](feishu-scopes.md)中的用户权限，并发布应用版本。
3. 打开「设置 → 飞书机器人」，在对应机器人卡片点击「分身」，发起连接并扫码确认。
4. 授权完成后，面板显示姓名、连接状态和凭证到期时间。

连接使用 Device Flow，不需要重定向 URL 或本机回调端口。App ID / Secret 复用所选机器人的配置。

当前每个插件数据目录只保存一份用户授权。切换应用或用户会替换这份授权；取消授权请求后，旧请求不会重新开启等待状态或在后续用户信息查询完成时落库。

## 主动读写飞书

Host 默认注册以下工具，普通会话与 Worker 均可使用，无需安装专用预设。

| 工具 | 输入与用途 |
|---|---|
| `feishu_avatar_me` | 查询当前授权用户的姓名、open_id 等信息 |
| `feishu_avatar_messages` | 用 `chatId` 读取私聊 / 群聊历史；支持时间范围、分页和本次结果内的关键词筛选 |
| `feishu_avatar_send` | 用 `chatId`、`openId`、`email` 之一指定收件人；用 `text` 或 `path` 发送卡片、图片或文件 |

文本卡片支持 Markdown、可选标题和标题颜色；传 `replyToMessageId` 可引用消息，需要同时提供 `chatId`，且仅支持文本卡片。
发送参数的当前校验上限为：正文 8,000 字符、标题 100 字符、图片 10 MiB、其他文件 30 MiB。相对文件路径以当前会话工作区为基准。

这些工具使用本人身份，`feishu_bot_*` 使用机器人身份。工具始终接受显式收件人参数，自动任务的目标会话由提示词约束。

历史查询的关键词只在本次拉取结果内筛选。当前没有文档、表格、日历或全文搜索工具；申请了对应 scope 并不代表已实现该能力。

## 开启自动处理

「分身」弹层按顺序分为三张可独立展开、收起的卡片：

- **账号卡片**：卡片头直接显示账号名称、连接状态与授权到期时间（`refresh_token` 的当前有效期，随刷新更新）；到期后提示重新授权。展开后查看授权详情，重新授权、刷新凭证或断开连接。
- **消息监听**：默认展开，管理监听开关、会话列表及每个会话的触发规则、回复对象。
- **自动回复设置**：管理转人工关键词、Worker 分组与预设、分身回复规则。

收起时仍可查看状态摘要，折叠不会丢失正在编辑的内容。点击右上角关闭按钮、按 Escape 或点击遮罩可关闭弹层；关闭前会提交待保存内容，保存失败则保留弹层与草稿供重试。正在扫码时，关闭也会取消本次授权。在「消息监听」中添加需要处理的会话，然后配置：

| 设置 | 行为 |
|---|---|
| 全部消息 | 处理该会话中符合发送者开关的新消息；私聊默认使用 |
| @我 / 回复我 | 群聊默认使用 |
| 关键词 | 关键词、@我、回复我满足任一条件即可 |
| 仅真人 / 包含机器人 | 关闭时排除机器人；开启时机器人与真人同等合批处理 |
| 转人工 | 命中后跳过当前待处理批次；后续消息继续正常处理。清空关键词可关闭 |
| Worker 工作区 / 预设 | 修改后，下次派发创建新 Worker；未指定时使用 DSH 默认工作区和 `standard` 预设 |
| 分身回复规则 | 所有自动 Worker 共用，编辑后自动保存，也可恢复默认模板 |

设置修改后自动保存。下拉框和开关即时提交；回复规则、转人工关键词和会话匹配关键词停止输入 600 毫秒后提交，离开输入框时立即提交，中文输入法组词期间暂停文本保存。「恢复默认模板」立即保存默认规则；空白内容保存为默认模板。保存状态与失败重试会直接显示在设置页。规则保存后从下一次模型请求生效，无需重建 Worker。

默认每 30 秒检查消息，再合批等待 30 秒；持续有新消息时最长等待 3 分钟，满 10 条立即派发。详细参数和边界以[监听与派发规则](user-message-monitor-design.md)为准。

「立即检查」拉取消息；「处理待办」立即尝试派发已记录的积压。新增监听从当前时间开始，不回补旧历史。停止监听会暂停未派发任务，已被 Host 接收的任务继续执行。

## 授权维护

- 「重新授权」发起新的扫码连接；「刷新 token」立即尝试续期。
- 「断开授权」取消设备授权请求并清除本地用户 token；它不是清空监听配置或撤销已接收任务的按钮。
- DSH 运行期间后台检查凭证；有效期取飞书实际返回值。过期且无法刷新时需重新连接。
- 设置页会提示缺少的 scope；配置文件迁移不会给已有 token 自动增加权限，需要重新授权。

## 排障

| 现象 | 检查与处理 |
|---|---|
| App Secret 缺失、应用不可用 | 在对应机器人的设置里补齐凭证 |
| 授权报 `20027`，或接口报 `99991679` | 检查应用用户权限、发布版本，并重新授权 |
| 刷新报 `20037` / `20073` | 当前 refresh_token 已失效，重新连接 |
| 工具不存在 | 确认 Host 插件启用，重新加载插件；无需修改预设 |
| 添加后没有旧消息 | 新监听不回补历史；按需用历史查询工具读取 |
| 新消息未入待处理批次 | 检查监听开关、触发模式、机器人开关及卡片是否仍在流式输出；本人消息只作为背景 |
| 有待处理消息但尚未派发 | 查看会话错误；检查 Worker 工作区 / 预设；可点击「处理待办」重试 |
| 待处理数归零但没有回复 | Host 接收任务即清队；查看对应 Worker，它可能尚未执行、决定不回复或执行失败 |
| 修改代码后行为未变化 | 重载 DSH 插件；源码更新不会自动替换已加载的模块 |

本地文件的位置、内容和保护方式见[开发架构](user-identity-architecture.md#持久化与并发)。
