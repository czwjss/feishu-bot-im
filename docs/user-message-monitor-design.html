个人收件箱没有事件推送

飞书的 WebSocket / 事件订阅绑定在应用或机器人上，只接收发给机器人的消息，不接收发给用户个人的消息。

  • 能做：轮询指定会话的历史消息。
  • 不能做：像飞书客户端一样实时收个人消息。
  • 不要承诺：“所有未读一条不漏”。

所以把“未读”换一个定义

每个会话保存一个时间游标。监听期间只处理游标之后、尚未处理过的消息；这就是本方案里的“新消息”。

Worker 收到什么，返回什么

worker ≠ sender

输入是已经清洗过的单会话上下文，不是整段飞书 JSON；输出是受限的决策对象，不是自由文本。Worker 使用不挂发送工具的专用预设，Host 只负责注入上下文和接收结果。

Worker 输入 · 单个会话chat: 群名 / 私聊名 trigger: @我 / 回复我 / 关键词 new_messages: 最近一批新消息 context: 最近 20 条上下文 sender: 姓名 + open_id mode: draft / auto task: 判断并生成回复
Worker 输出 · 结构化{ "action": "reply | ignore | ask", "reply": "给对方的回复正文", "reason": "简短判断理由", "confidence": "high | medium | low" } 低置信度 / 高风险 → 强制人工

默认 草稿审核

Worker 生成草稿后，Host 通过机器人身份把审核卡发给你，不直接发到对方会话。

01 审核卡展示：谁发的、原消息、草稿。 02 你点「发送 / 编辑 / 忽略」。 03 Host 以用户身份回复原消息。 04 记录 message_id，关闭任务。

白名单 自动回复

Worker 给出发送建议，只有策略全部通过才自动发；发完给你一张回执卡。

01 检查会话 / 发送者白名单。 02 检查置信度、静音、限频、循环。 03 以用户身份回复原消息。 04 给你回执，保留撤回入口。
关键边界：Worker 只负责理解与起草，不能调用 feishu_avatar_send，也不能直接写飞书。所有外部发送统一经过 Host 的 Policy + Outbound Sender，保证可审计、可限频、可人工拦截。

私聊和群聊各有一个专用 Worker Session，上下文不串台；同一会话同一时间只处理一批，避免并发抢答。

三条隔离规则

避免把不同人、不同群、不同话题混进同一个上下文。

  • 批次只属于一个 chat。不同群、私聊的消息永不合并。
  • Worker 按会话绑定。一个 chat 对应一个长期 Worker Session。
  • open_id 只是发送者。同一个人出现在私聊和群里，不合并会话。

群聊和私聊的关系：它们在飞书里都是 chat，只是 chat_mode 不同。处理管线相同，差别在触发规则、回复方式和白名单。群聊有话题时，可把 threadId 也加入 Worker 键，做成“一话题一 Worker”；默认仍是一个群一个 Worker，话题作为上下文标记。

三种回复模式

按会话独立选择
watch

只监听

把新消息投递到 DSH，不生成回复。

适合先观察消息量和误触发率
draft · 推荐默认

草稿确认

生成回复草稿，用户在 DSH 里发送、编辑或忽略。

适合私聊和大多数群聊
auto · 谨慎开启

受限自动

只对白名单会话和联系人自动回复，带频率和内容护栏。

验证误触发率之后再打开

自动回复的护栏

宁可少回，不要回错
scope

只允许白名单

会话 + 发送人双重白名单；外部群和未知发送者一律转草稿。

rate

限频与静音

单会话最短 10 秒、每小时 20 条；全局每小时 100 条；夜间静音。

loop

防止自问自答

跳过自己；记录已发 message_id；连续自动回复 3 次后暂停。

risk

高风险转人工

金额、合同、审批、法律、医疗、敏感个人信息，都不自动发。

fail

失败不丢消息

入站游标和出站队列分离；发送失败重试，不重新消费入站。

off

随时可停

监听总开关、单会话暂停、全部暂停；停用不删除游标。

自动回复是一项外部写操作。默认关闭；打开前先跑一段时间的 watch 和 draft，看真实误触发率。

可靠性的关键：两条队列

不要用一个游标同时管“读”和“回”
入站游标ingest cursor

消息保存到处理队列后推进。失败重读，保证不漏；不因为回复失败而回退。

出站任务outbound jobs

发送失败用同一 uuid 重试；成功记录 message_id。避免重复发送，也不丢消息。

存储

monitor.json 保存监听配置；monitor-state.json 保存游标、去重集合和任务。两者 0600，不保存 token，默认不落完整正文。
