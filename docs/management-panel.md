# 飞书机器人IM 管理面板

从 DSH 侧栏进入「飞书机器人IM」，先在顶部选择机器人，再通过「状态、会话、分身」页签管理。新进入的机器人默认展示状态，已有的有效页签选择继续保留。右上角「添加机器人」提供手动添加与扫码添加，不再注册独立的飞书设置页。插件安装与启停仍由 DSH 插件管理负责。

## 页面与职责

| 位置 | 内容 |
| --- | --- |
| 顶部机器人导航 | 左侧飞书机器人IM 标题，中间纯文字机器人名称列表（可横向滚动；正常绿色、故障红色，其余状态中性色，选中项显示细下划线），右侧添加入口；选中机器人自动滚动到可见位置 |
| 状态 | 上下两个独立区域：上方为当前机器人，展示名称、连接状态、应用信息、运行观测和错误；已连接时在下方展示可编辑的机器人设置，操作区提供连接诊断、刷新、重连、补齐权限及「…」删除入口。下方为飞书分身，展示本人姓名、授权状态、Open ID、授权与访问凭证到期时间；重新授权、刷新凭证直接展示，断开授权收进「…」并二次确认。扫码与授权错误直接显示在页内，有效授权后在分身信息下方直接展示自动回复设置。最近事件与错误不是持久化的消息处理历史 |
| 会话 | 当前机器人的会话目录、搜索、会话类型（全部类型 / 群聊 / 私聊）与绑定状态组合筛选、Session 摘要、绑定 / 更换 / 解绑、原生跳转、下次新建会话的默认值及覆盖来源 |
| 分身 | 左侧分区展示手动添加的群聊与自动发现的私聊，右侧显示原生 Worker。私聊总开关默认关闭。群聊监听设置和会话消息详情在抽屉中维护。身份、授权信息及自动回复设置集中在状态页 |

机器人默认值和分身规则延续自动保存。机器人名称取已有显示名称或飞书返回的名称，页面不提供改名操作。同一机器人的页签按需挂载，访问后保留挂载以保留草稿；状态页和分身页共用监听状态查询，仅在需要时轮询。切换机器人或打开 Session 前先提交待保存内容，失败时保留原机器人及草稿，并回到对应编辑页重试。切换成功后重新建立该机器人的视图，查询结果和草稿不会沿用上一台机器人。

浏览器页面隐藏时暂停管理轮询；Host 上的消息监听不受影响。未绑定的会话在右侧详情中点击「绑定会话」，按名称、Session ID 或工作区路径搜索已有 DSH 会话并确认。已有绑定可点击「更换绑定」，替换前二次确认；已失效的绑定也可直接更换。选择器只在打开时读取 Host 目录，支持刷新和增量展示，切换机器人或飞书会话时关闭未提交的选择。

绑定保留所选 Session 的标题、历史、模型与工作区，不创建新 Session、不发送消息或提交提示词。下一条触发消息进入所选 Session。候选包含各工作区的普通会话和空白会话，排除归档、子智能体及需要格式迁移的会话；运行中、已被其他聊天绑定或属于分身 Worker（含历史 Worker）的候选显示不可选原因。提交时再次检查可用性与归属，Host 读取失败时不会修改绑定。

会话详情的「解绑」需二次确认，支持清理已失效的 Session 绑定，只解除当前机器人的这条关联，保留原 DSH 会话、历史及聊天配置，不发送飞书消息。下一条触发消息创建新会话；仍在处理、等待执行或本地排队时需等待结束再调整绑定，不取消任务或丢弃消息。原有飞书 `/menu` 操作保留。解绑后，仅靠绑定出现在列表中、且飞书目录不可见的会话会从目录移除。

`chat.sessions.list({ botId, chatId })` 返回当前绑定与候选摘要，不读取会话正文。`chat.bind({ botId, chatId, sessionId, expectedSessionId })` 使用显式目标，`expectedSessionId` 为页面读取的原绑定，未绑定时传 `null`。事务比较原绑定，拒绝覆盖入站消息或其他页面后来建立的关联；主面板绑定写入串行执行，避免两个机器人同时从页面选择同一个 Session。在线机器人与入站投递使用同一会话队列，提交前后检查连接状态及待执行任务；不会丢弃已有排队消息。成功后立即更新列表及详情，后续目录刷新失败仍保留已确认的绑定。

`chat.unbind({ botId, chatId, sessionId })` 要求三个明确的 ID；存储事务对比原 Session ID，拒绝旧页面解除后来建立的新绑定。操作按飞书会话与入站投递串行执行，机器人离线时仍可清理本地绑定。重复解绑已解除的关联不再写入。前端收到成功后立即更新当前绑定，再刷新目录；目录刷新失败不会恢复已解除的关联。

机器人与分身的文字操作按钮悬停或获得键盘焦点 2 秒后显示提示；移开、点击、按 Escape 或离开页签时收起。手动刷新更新当前机器人目录、运行状态及分身授权快照，不执行凭证诊断、重建连接或拉取分身新消息。分身授权由状态页与分身页共用查询，在这两个页签中定期更新，等待扫码时缩短轮询间隔；主动拉取新消息使用分身页的「立即检查」。重连会先断开旧连接再重新建立，连接中时禁用重复点击。补齐权限继续走当前机器人的应用扫码授权流程。

状态页直接展示完整信息，不再提供详情弹窗或复制信息。操作区右侧「…」展开「删除机器人」，点击后明确确认机器人名称，确认才调用删除；取消不删除。删除前提交待保存配置，失败时返回对应编辑页保留草稿。删除入口仅在状态页，不在配置页重复展示。

## 布局与内嵌 Worker

主面板采用占满 Host 主区域的单页应用布局。顶部标题、可横向滚动的机器人导航、添加入口和模块页签固定；原公共机器人头部并入状态页，普通模块在内容区滚动。分身页的监听列表、原生对话和抽屉各自管理滚动，外层页面不再随对话一起滚动，Worker 使用剩余高度而非固定视口高度。

状态页的机器人与分身各占一张完整宽度的卡片，机器人在上、分身在下，分别放置标题和对应操作。机器人应用信息与运行观测宽屏双列、窄屏单列；静态会话默认设置由下方的可编辑设置替代。机器人设置通过「通用 / 私聊 / 群聊」切换：通用按会话默认、模型与输出分组；私聊按消息处理、上下文注入分组；群聊按消息处理、访问权限、上下文注入分组。设置分区宽屏双列、窄屏单列，切换时提交待保存编辑，失败提示与重试入口始终留在设置栏，草稿保留。分身凭证信息宽屏三列、窄屏换行，长 ID 和路径允许换行；卡片按内容自然增高，共用状态页滚动。

机器人未连接时不加载或展示配置。分身未授权、授权到期或缺少消息功能所需权限时隐藏自动回复设置，初次不可用时也不加载其设置目录。仅缺少新增云空间权限时，已有自动回复设置仍可使用。已经打开的编辑组件在连接失效时隐藏并保留草稿，恢复后继续编辑与重试，断开授权前先提交待保存设置。自动回复设置宽屏左侧为转人工与处理会话配置、右侧为回复规则，窄屏上下排列，编辑区限制最大宽度。

分身页默认选择第一个监听会话，只有选中的 Worker 获取原生会话引用。点击其他会话直接切换右侧 Conversation；没有 Worker 时展示等待首次派发，不因查看而创建会话。窄屏切换为列表 / 对话两个视图，返回列表保留当前原生输入绑定。搜索只过滤列表，不改变当前会话。

分身授权详情直接在状态页展开。「连接分身」与「重新授权」均在页内显示二维码，一次申请分身的消息与云空间权限。「取消扫码」只取消当前授权请求，切换页签或机器人不自动取消。断开授权需确认，只清除本地用户凭证，保留监听配置与 Worker 会话。分身页的「监听设置」「查看消息」按需打开抽屉，不替换原生对话。抽屉使用原生 modal dialog，支持焦点约束和 Escape；关闭前提交草稿，保存失败时保持抽屉与草稿。消息正文只在详情抽屉打开后查询，分类中的「上下文消息」仍代表本地缓存，不是处理回执；消息 ID 折叠显示。历史 Worker 从消息详情打开，「返回当前 Worker」回到当前绑定。「独立打开」仍可跳到 DSH 主会话。查看和切换不提交提示词、不触发派发。

`client/index.js` 在 `main` 下声明严格 Session 作用域的 `im-feishu.worker.conversation` 子 slot。客户端按需通过 `sessions.retain(sessionId, { source: 'feishuAvatar' })` 获取独立引用，并用主 slot 提供的 `SessionProvider` 绑定该引用，再渲染子 slot。会话尚未进入浏览器目录时先刷新原生 Session 目录。子 slot 复用 `conversation.content` Factory（`variant: 'embedded'`），将局部 View 固定为 Chat；原生正文、Composer 和待处理交互共用这个 Worker 的 Session 作用域，不修改全局主会话选择。

同一机器人的页签切换、抽屉开关和窄屏返回列表都保留内嵌引用；切换 Worker、移除选中监听会话、切换机器人或卸载页面时释放旧引用，迟到的加载结果被忽略。释放只结束客户端查看，不取消或归档 Host Worker。打开历史 Worker 保留原 Session ID。打开失败支持重试；未提供所需客户端能力的 DSH 版本可以使用独立打开。工作区列表保持原样。

## 分身归属

当前每个插件数据目录仍只有一份用户授权和一份监听配置，以授权配置中的 `config.app.botId` 确定归属。只有实际归属的机器人加载分身数据；状态页读取监听设置，分身页按需读取消息并查看 Worker；其他机器人显示未连接状态和当前归属，可主动发起新授权。切换授权应用会沿用现有监听配置，状态页在连接前明确提示这一点；本次没有把单授权实现伪装成每个机器人拥有独立分身账号。

分身管理请求携带 `botId`，服务端校验当前归属后才读取或修改监听、刷新凭证或断开授权。授权切换后，旧页面的延迟保存会被拒绝，不会修改新的归属；普通会话中的全局 `feishu_avatar_*` 工具继续使用当前授权。

## 数据含义

- 会话目录来自机器人可见的群及已知绑定，包含已知私聊；不是本人完整收件箱。机器人和分身各自持有会话关系。
- 会话类型使用飞书目录的明确类型；默认群列表未返回模式时按群聊处理。历史绑定缺少信息时查询会话详情的 `chat_mode`（`p2p` 为私聊，`group` / `topic` 为群聊），也可回退到实际收到消息时记录的类型。`chat_type` 的公开/私有属性不用于区分私聊和群聊，不按名称或是否绑定猜测；信息不足时显示「类型未知」。详情查询复用缓存，手动刷新会重新获取，查询不会改写绑定或读取消息正文。
- 同名或相同 chatId 的不同机器人会话，以 `botId + chatId` 区分。重复的 Session 绑定以及与分身 Worker 的重叠会显示冲突；历史 Worker 仍有动态上下文，因此也参与冲突判断。
- 「会话不可用」表示 Host 本次返回的会话列表中找不到该 Session，不能单凭这个状态断定会话被删除。Host 列表读取失败则显示「状态未知」。单个机器人发现失败会保留已知绑定并显示警告。
- 当前模型和工作目录读取 Host Session 摘要，缺失时显示 `—`。「下次新建会话」单独显示机器人默认值和会话覆盖，不将默认配置冒充当前 Session 状态。
- 分身「最近投递」表示 Host 接受了批次。仍然派发成功即清队，不等模型回复，也不新增回复确认协议。
- 消息详情按需读取受现有容量限制的本地快照，区分待处理、上下文消息和当前发送者配置排除的消息。它不是逐批审计记录，也不推断模型是否决定不回复。
- 「计划派发」来自当前内存定时器；暂停时清空展示，重启后按调度恢复。它不是发送承诺。
- 「派发本批」只派发选定会话；「重试派发」沿用全量积压派发。两者都调用现有引擎，遵守监听开关及原有筛选规则。
- 打开页面和查看消息都是只读操作；「连接诊断」只校验凭证和当前长连接，不发送测试消息、不自动重连。诊断结果保留检查时间。

## 实现入口

| 文件 | 职责 |
| --- | --- |
| `client/index.js` | 侧栏、主界面与 Worker 子 slot 注册；独立打开使用 `uiWorkspace.openSession` |
| `client/workspace.js` / `workspace-style.js` | 机器人选择、页签、草稿提交、状态与响应式布局 |
| `client/conversations.js` / `workspace-model.js` | 会话列表、筛选、绑定与执行状态区分 |
| `client/session-binding.js` | 按需加载、搜索、选择和确认已有 DSH 会话 |
| `client/bot-status.js` / `status-settings.js` | 机器人与分身状态、连接条件下的配置展示及草稿保留、诊断与删除入口 |
| `client/action-button.js` / `action-menu.js` | 操作按钮的 2 秒提示、统一的「…」菜单与切页清理 |
| `client/bots-panel.js` / `bot.js` | 选中机器人的配置、接入与连接操作 |
| `client/identity.js` | 分身身份与归属校验、页内授权操作与扫码状态 |
| `client/avatar-reply-settings.js` | 状态页内的转人工、Worker 分组与预设、回复规则及自动保存 |
| `client/avatar-workspace.js` / `avatar-style.js` | 监听会话选择、Worker 主从布局、单会话设置与消息抽屉 |
| `client/drawer.js` / `monitor-detail.js` | 原生抽屉、按需消息快照与历史 Worker 入口 |
| `client/worker-conversation.js` | Worker 引用生命周期、SessionProvider 与原生 Conversation Factory |
| `src/management.js` | 跨 Runtime 与 Host Session 的只读聚合，不建立第二份状态存储 |
| `src/chat-binding.js` | 主面板的候选会话、归属校验与绑定提交，复用原有绑定存储 |
| `src/runtime.js` / `bridge.js` | 机器人会话、默认值及运行观测投影 |
| `src/user-identity/monitor.js` / `auto-reply.js` | 分身快照、局部派发、被动调度观测 |

`management.snapshot({ botId?: string, refresh?: boolean })` 返回 `{ updatedAt, bots, chats, warnings }`。自动轮询使用全量快照并复用目录缓存；手动刷新传入当前 `botId` 和 `refresh: true`，只加载该机器人的状态与目录，返回的 `bots` / `chats` 也仅包含该机器人。其他机器人的绑定通过现有本地索引检查冲突，不访问其飞书目录。前端只合并该机器人的数据，保留其他机器人及其警告；空或未知 ID 会报错，不退回全量刷新。`user.monitor.detail({ botId, chatId })` 返回选定监听会话的消息与 Worker 快照，不拉取消息、不写飞书。管理接口继续使用现有 DSH 已认证 RPC 通道，不返回 token 或 App Secret。

本期没有完整处理时间线、逐消息跳过原因或发送结果追踪。后续可以基于消息、批次和 Session 关联增加结构化事件，不应通过改变清队时机来实现观测。
