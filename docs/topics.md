# 群聊话题使用手册

## 话题是什么

话题 = **以你的消息为根、由独立会话承载的一段工作**。

- 机器人回复你的 `/topic` 消息时用"线程回复"，飞书会把它变成一条**话题**；
- 话题有自己独立的一条 DSH 会话，与群主会话互不影响；
- 每个群独立编号（#1、#2…）。

## 创建

在群里 @ 机器人，发送：

```
@机器人 /topic 关于我帅不帅的讨论
请从客观、表达、叙事三个维度分析
```

- 第一行是标题（最长 20 字，超出截断）；
- 后面的行是这次要讨论的正文，作为新会话的第一条任务；
- 机器人**立即新建会话并回答**，回答线程挂在你的这条消息下面，飞书自动把它变成话题。

话题的工作区 / 预设 / 模型**继承群主会话**（不继承会话历史）。

## 在话题里继续

话题内**只有 @ 机器人**的消息才会被处理，不 @ 的发言机器人不理。

```
（话题内）@机器人 继续第二步
```

## 查看列表

群主会话里 @ 机器人：

```
@机器人 /topic
```

机器人回文本列表：

```
话题列表：
#1 关于我帅不帅的讨论
#2 整理测试报告
```

## 同步结论（/topic-sync）

话题不会"关闭"，可以一直聊下去。需要把结论带回主会话时，在话题内 @ 机器人：

```
@机器人 /topic-sync
```

会发生：

1. 话题会话生成一段不超过 300 字的结论摘要（回答出现在话题里）；
2. 摘要随主会话的**下一条消息**以 `<feishu_bot_topic_sync>` 前置块注入（与来源块同机制，不写进常驻指令）；
3. 主会话里出现一条提示：`话题 #N「标题」已同步到主会话。`

## 边界与限制

| 情况 | 行为 |
|---|---|
| 话题内再发 `/topic xxx` | 不允许嵌套创建，提示回群主会话开新话题 |
| 话题会不会关闭 | 不会，会话一直可用 |
| 同步会不会重复 | 每次 `/topic-sync` 都会新增一条摘要，全部保留 |
| 群里普通发言（不 @、不引用） | 不响应 |
| 群主会话里引用/回复机器人消息 | 视为被叫到 |
| 话题内不 @ | 不响应 |
| 关闭会删历史吗 | 不会，会话保留 |
| 数据存在哪 | `state-<botId>.json` 的 `topics`（含 `rootMessageId`、`threadId`） |

## 与旧版卡片方案的区别

- 不再发"话题公告卡"，根节点是**你发的那条消息**；
- 没有"结束话题"的概念，会话一直可用；结论通过 `/topic-sync` 手动同步回主会话；
- 话题内只认 @，避免线程里任何闲聊都触发机器人。
